# sync-hermes-context.sh — mirror /opt/data/workspace/hermes-context/ (or $HERMES_CONTEXT_SRC)
# into /workspace/hermes-context/ (or $HERMES_CONTEXT_DST).
# One-way host->workspace sync (A2). rsync primary, tar fallback (A4), both converge to

    --dry-run)  DRY_RUN=1 ;;

  esac
done

=== README.md ===
# sync-hermes-context

One-way sync of the hermes context tree from the host mount into the workspace.
Source of truth is the host mount; the workspace copy is a mirror — stale entries
are deleted at any depth on every run.

## Paths (contract, env-overridable)

- Source: `HERMES_CONTEXT_SRC` (default `/opt/data/workspace/hermes-context/`)
- Destination: `HERMES_CONTEXT_DST` (default `/workspace/hermes-context/`)

Env override is the mandated parameterization mechanism; deployed defaults are
production values. Sync is strictly one-way (host -> workspace); nothing is ever
written back to the source.

## Install

1. Copy the script outside the mirrored tree:

   ```
   install -m 0755 sync-hermes-context.sh ~/.local/bin/sync-hermes-context.sh
   ```

2. Copy the user units:

   ```
   mkdir -p ~/.config/systemd/user
   cp hermes-context.service hermes-context.timer ~/.config/systemd/user/
   systemctl --user daemon-reload
   systemctl --user enable --now hermes-context.timer
   ```

The service runs `%h/.local/bin/sync-hermes-context.sh` as a oneshot unit; the
timer fires every 6 hours (`OnCalendar=*-*-* 00/6:00:00`, `Persistent=true`).
Check status with `systemctl --user status hermes-context.timer` and
`journalctl --user -u hermes-context.service`.

The script also runs standalone (cron, manual) with no systemd dependency.

## Dry-run test

```
~/.local/bin/sync-hermes-context.sh --dry-run
```

`--dry-run` emits a plan to stdout only: no files or directories are created
anywhere, no log is written, and if the destination does not exist it stays
absent. Verify the destination is byte-identical (or still nonexistent) after a
dry-run before doing a real run.

There is also `--verify`: compares an existing destination against the source
(contents, recursive directories, symlink targets) and exits nonzero on any
mismatch, including when the destination does not exist.

## Sync strategy

- Primary: `rsync -a --delete --copy-links=no SRC/ stage/` — contents of the
  source (no nesting) staged first.
- Fallback (no rsync available): `tar -C SRC -cf - . | tar -C stage -xf -`
  followed by a recursive reconcile that deletes stale entries at all depths.

Both paths converge identically to an exact recursive mirror: same contents,
same recursive directory structure, symlinks preserved as symlinks. The staged
copy is content-verified against the source (files, directories, symlink
targets) before the destination is touched; if verification fails the run exits
nonzero and the destination is left untouched. Only after a content-compared
staged copy exists is the destination replaced wholesale, which is what removes
stale files and directories at any depth on both sync paths.

## Refusals (guards)

The script refuses — cleanly, with a cited law and nonzero exit, before any
write — when:

- A18: source or destination is degenerate (`/`, empty, `.`)
- A12: `realpath(SRC) == realpath(DST)`, either path is an ancestor/descendant
  of the other, or the destination (through symlinked ancestors) resolves into
  the source — checks are realpath-based, not lexical prefix checks
- A14/A15: the script-owned log dir, staging path, or the script's own
  entrypoint directory would collide with (be inside, contain, or equal) the
  source or destination boundaries

Staging lives under `~/.cache/hermes-context/` (never inside SRC, DST, or
TMPDIR-root), the log is `~/.cache/hermes-context/sync.log` (always outside the
mirrored tree), and the installed entrypoint is outside the mirrored tree, so a
sync can never delete its own entrypoints or logs. Source survival outranks
freshness: the destination is only replaced after a verified copy of the source
exists elsewhere.

## Logs

Real runs append to `~/.cache/hermes-context/sync.log`. Dry-runs write nothing,
including no log.

## KNOWN_LIMITATIONS

- Exotic filenames (newlines/control characters): not guaranteed lossless under
  self-verification (A21).
- Adversarial environment-variable combinations beyond the A14 owned-path guard
  (e.g. hostile `TMPDIR`/`HOME` redirections aimed at the destination) are out
  of scope (A14).
