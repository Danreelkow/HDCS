What we're building: a script that keeps a folder of Hermes context files automatically copied from one location to another, plus the pieces that run it on a schedule.

**Folders involved**

- The source of truth is `/opt/data/workspace/hermes-context/` on the host.
- The copy lives at `/workspace/hermes-context/`.
- The script and docs go in `/workspace/hdcs/hermes-sync/`, the script itself into `~/.local/bin/`, and two small systemd files into `~/.config/systemd/user/`.
- A simple one-line log of each run goes to `~/.cache/hermes-context/sync.log`.

**How it works**

- Copying goes one way only: host to workspace. Nothing is ever written back to the source.
- The copy is a true mirror: if a file disappears or changes at the source, the copy matches — old files are deleted. The tool of choice is rsync with its delete option; if rsync isn't installed, the script falls back to plain copying (using `cp -a`, with a tar-pipe as a last resort).
- "Mirror" means files, folder structure, and symbolic links match exactly. It does not promise matching timestamps, permissions metadata, or hardlinks.
- The script is idempotent: running it again changes nothing if things already match, and it prints one short summary line per run.

**Scheduling**

- A systemd user timer runs the sync every six hours using `systemctl --user`, so no root or admin rights are needed.
- The script also works fine when run by hand, on its own.

**Dry-run mode**

- There's a dry-run option that performs the entire check but writes absolutely nothing — not even log entries. After a dry run, the destination is either byte-identical to before or didn't exist and still doesn't.

**Safety guards**

- Before any destructive operation, the script checks that the source and destination are genuinely different folders — it refuses to run if they're the same path, one contains the other, or the paths are degenerate (empty, root, etc.). It uses real resolved paths for this comparison, not just the typed strings.
- Deletions happen safely: changes are staged first, verified, and only then applied to the destination — the destination is never touched until the new state is confirmed good.
- Scratch/temp files are created only in concrete, owned locations outside the destination folder, with a fallback to the system temp directory if needed.
- Protecting the source matters more than having the freshest copy: if anything looks risky, the source is left untouched.

**Environment overrides**

- The paths are set as sensible defaults, but they can be overridden with environment variables — that's the intended design, not a loophole. Deployed default paths don't lock the script down.

**Quality bar**

- Bugs that would appear in normal everyday use must be fixed before delivery. Truly exotic edge cases can be documented in a "known limitations" section instead.

**Process**

- Work proceeds in phases: plan, build, verify (by someone other than the builder), deliver. If verification fails, there are at most two fix-and-recheck rounds before we stop and report honestly what's done, what was decided, and what's still open.
