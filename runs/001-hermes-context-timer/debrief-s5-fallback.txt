# Debrief: Hermes Context Sync Tool

## What this is
A small deploy tool that keeps a copy of your hermes-context folder in sync. The source path is /opt/data/workspace/hermes-context/ and the destination is /workspace/hermes-context/. It runs automatically every six hours using systemd user units, so no root required. The script also works standalone if systemd isn't available.

## How it syncs
The sync is rsync-based, with a cp -a fallback if rsync isn't installed. Both paths are idempotent — safe to run repeatedly — and both converge to the exact same end state: the destination becomes a mirror of the source, recursively, including contents, structure, and symlinks. Stale files at the destination are deleted so it's an exact mirror. Metadata like timestamps and hardlinks are not compared. A verification step checks the mirror and exits with an error if anything doesn't match.

## Dry-run behavior
There's a dry-run mode that performs no writes — zero changes of any kind. If the destination doesn't exist, a dry run leaves it nonexistent; only a real run creates it with mkdir -p. Logs always go to ~/.cache/hermes-context/, never inside the destination, so even a dry run writes nothing there.

## Safety guards
The sync is one-way, host to workspace; it never writes back to the source. The script refuses dangerous configurations: if source and destination are the same path, one contains the other (ancestor or descendant), or paths are degenerate (empty, ".", "/"), it refuses. Destination-level symlinks are also refused. Every refusal cites a rule from a closed list — no invented ownership checks beyond what the OS provides.

The write order is: stage into a temporary directory (mktemp -d under a validated parent), verify the content, then touch the destination. This applies to both the rsync path and the cp fallback. Temporary bookkeeping files never overwrite mirror files, and no fixed working names collide with source contents.

Environment variables can override the deployed defaults — that's the contract; deployed paths are the production values. Unset variables fall back to defaults; set-but-empty values are refused. Environment overrides pointing at script-internal paths are guarded with a boundary-aware owned-path check; adversarial combinations beyond that guard are documented as known limitations, not failures.

## Failure severity
Only normal-operation data loss or corruption counts as a failure. Exotic filenames and other edge cases go into known limitations instead.

## Deliverables
Four files: sync-hermes-context.sh, hermes-context.service, hermes-context.timer, and README.md. Installed to ~/.local/bin (or /workspace/hdcs/bin) and ~/.config/systemd/user/.

## Process
Work ran in four phases — plan, scoped build, verify, deliver — with an independent verifier and up to two fix cycles before a READY/NOT_READY gate.
