### Reverse-Gate Contract

This setup involves a standing sync service that mirrors the source directory `/opt/data/workspace/hermes-context/` to the destination directory `/workspace/hermes-context/` every 6 hours using a systemd user timer. The script is designed to be standalone and uses rsync as the primary tool for synchronization, with `cp -a` as a fallback.

**Key Details:**

- **Source Path:** `/opt/data/workspace/hermes-context/`
- **Destination Path:** `/workspace/hermes-context/`
- **Dry-Run Mode:** Performs no writes
- **Systemd User Units:** No root access required

**Requirements:**

- The source path must be `/opt/data/workspace/hermes-context/`.
- The dry-run mode must perform no writes.
- Systemd user units are used, and no root access is needed.

**Resolved Points:**

1. **Source Path:** The canonical source path is `/opt/data/workspace/hermes-context/`.
2. **Sync Direction:** The sync is one-way from the host to the workspace with no writeback to the source.
3. **Units:** Systemctl user units are used, no root access required.
4. **Rsync Availability:** Rsync is detected, and `cp -a` is used as a fallback.
5. **Stale Files:** Stale files at the destination are deleted to ensure an exact mirror.
6. **Dry-Run Logs:** Dry-run logs are stored outside the destination directory.
7. **Mirror Equivalence:** The mirror includes contents, structure, and symlinks but excludes metadata, timestamps, and hardlinks.
8. **Severity Bar:** Data loss or corruption in normal operation is a fail; exotic cases are noted as known limitations.
9. **Destructive Misconfiguration:** Realpath identity is guarded to prevent misconfigurations.
10. **Environment Variables:** Internal paths are guarded to prevent boundary issues.
11. **Destination Absent:** If the destination is absent, it is created in a real run; dry-run does not create it.
12. **Environment Override:** Environment overrides are the contract; deployed paths are production values.
13. **Ownership Checks:** No ownership checks beyond the OS.
14. **Staging Order:** Staging order is validated to prevent name collisions.
15. **Exotic Filenames:** Exotic filenames are noted as known limitations.

**Workflow:**

- **Phases:** Plan, scoped-build, verify, deliver.
- **Builders:** Dynamic.
- **Verifier:** Decorrelated.
- **Gate:** Ready or Not Ready.
- **Fix Cycles:** Maximum of 2.

**Handoff:**

- **State:** Initial state plus changes to final state.
- **Report:** Includes done, unresolved, open, and validation status.

**Constraints:**

- Source path must be kept verbatim.
- Dry-run mode must perform no writes.
- Systemd user units must be used without root access.
- Sync never writes to the source.
- Both sync paths must converge to an identical end state.
- Dry-run must result in zero writes; destination must be nonexistent if absent after dry-run.
- Log directory and install paths must always be outside the destination.
- Staging order must be stage -> content-verify -> touch DST.
- Refuse source/destination identity, ancestor/descendant, degenerate paths, and destination-level symlinks.
- Concrete owned-path guard must be boundary-aware.
- No invented ownership scope; law list closed to amendment only.
- Script working names must not collide with source contents.
